## 4. Decisions made this session

- **Decision** — Filed and merged three separate PRs (one per bug) instead of one bundled PR.
  - **Rationale** — Each bug had a distinct file scope (no overlap), clean acceptance criteria, and could be reviewed independently. Three Engineer subagents ran in parallel via `isolation: "worktree"`. Bundling would have serialized review.
  - **Consequence** — Future bug clusters with non-overlapping file scopes should be parallelized via `isolation: "worktree"` Engineer dispatches. Don't pre-bundle out of habit.
- **Decision** — `_handle_tool_calls` returns `is_error=True` `tool_result` blocks instead of propagating tool exceptions, including for the unknown-tool branch.
  - **Rationale** — The Anthropic tool-use protocol explicitly supports `is_error=True`; the LLM can read the error, retry with valid args, or skip the candidate and continue. Crashing the whole scan was strictly worse.
  - **Consequence** — Any future agent tool that needs to fail must do so via `raise`, NOT by returning a special sentinel — the wrap path now catches and reports it correctly. See `agents/base.py:88-115`.
- **Decision** — `tools/risk.py::calculate_position` raises `ValueError` for non-positive `atr`, `entry_price`, `portfolio_value`, `risk_pct` (defense-in-depth on top of the wrap).
  - **Rationale** — Without this, an LLM-hallucinated `atr=0` raises `ZeroDivisionError` deep in the math; with it, the LLM sees a clear `ValueError: atr must be > 0 (got 0)` it can correct.
  - **Consequence** — When wiring future risk math, follow this pattern: validate inputs at the top of the function, raise `ValueError` with the bad value in the message.
- **Decision** — Per-trade exception in `run_monitor` records `MonitorAction(... "hold", "skipped_error", 0.0)` rather than skipping the trade entirely from the action list.
  - **Rationale** — Keeps `notify_monitor`'s "checked" count honest, marks the trade as still-holding (it didn't actually close), and is plainly visible in any future debugging of the action log.
  - **Consequence** — `MonitorAction.reason` now has a fifth allowed value `skipped_error` not yet listed in the docstring at `monitor/position_monitor.py:15`. Cosmetic. Worth a one-line fix during the next monitor edit.
- **Decision** — Cleaned up 5 agent worktrees + 16 stale local branches at session end.
  - **Rationale** — Local checkout had drifted onto `pr-119` because the Reviewer/Lead subagents did `gh pr checkout` and didn't restore. Worktrees from this and prior sessions had piled up.
  - **Consequence** — `/opt/trading-bot` is now clean on `main`. Only one non-session worktree remains (`readme-ssh-tweak`, not from this session). If subagents do `gh pr checkout`, restore the main checkout afterwards.
