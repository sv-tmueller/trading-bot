## 4. Decisions made this session

- **Decision** — `team_leader.place_order(dry_run=True)` runs the deterministic safety stack (`check_exposure_for_new_order`, `validate_bracket_params`) — only `place_market_order` and `insert_trade` are skipped on dry-run.
  - **Rationale** — A dry-run that silently skips the gates is a false-positive smoke test (recall `MEMORY.md::project_2026_04_30_first_safe_run`: gate fires 4-for-4 in real runs). Engineer's first cut preserved the legacy fast-path; reviewer pushed back; user's brief confirmed.
  - **Consequence** — `python main.py scan --dry-run` is now a load-bearing pre-deploy smoke test. Don't skip it before merging changes that touch the order-placement path.
- **Decision** — Panic CLI exception handlers include `traceback.format_exc()` in the `notify_error` payload; `notify_error` already keeps both head and tail (PR #117).
  - **Rationale** — User's 21:46 errors (`maximum recursion depth exceeded`, `Cannot operate on a closed database`) could not be reproduced by code-reading or local repro. Speculative fixes are riskier than instrumentation.
  - **Consequence** — Next recurrence will land the full stack in Discord. If the bugs reappear, jump to the actual frame; do not "fix" the recursion or DB code paths preemptively.
- **Decision** — Panic CLI audit log uses INSERT-then-UPDATE pattern: pre-broker INSERT records intent (so a crash mid-run is recoverable from DB); `finally`-block UPDATE records per-action result (e.g. `cancel-orders=ok(N)` / `cancel-orders=fail(<exc>)`).
  - **Rationale** — Single row per panic invocation, but with both states. Preserves the partial-recovery property while giving operational visibility into what actually happened.
  - **Consequence** — `agent_logs.full_reasoning` for a panic row will have shape `intent | result: ...`. Future tooling that parses these rows must handle the two-phase shape.
- **Decision** — Panic `--liquidate` mandatorily requires `--confirm`; without `--confirm` it is dry-run-only and exits non-zero.
  - **Rationale** — Destructive action; accidental shell history re-run could close every position.
  - **Consequence** — Any scripted automation calling `panic --liquidate` must also pass `--confirm`. Document this in any future runbook.
- **Decision** — Panic `--pause` writes `.env` anchored at `Path(__file__).resolve().parent / ".env"`, NOT cwd-relative.
  - **Rationale** — Reviewer caught the cwd-relative footgun. Operator under stress will not always cd into `/opt/trading-bot` first.
  - **Consequence** — Any future helper that touches `.env` from `main.py` should follow the `_REPO_ROOT` pattern at `main.py:206`.
- **Decision** — Did NOT add a `panic --resume` flag in this round.
  - **Rationale** — Out of scope for issue #103. User can `sed -i 's/^TRADING_PAUSED=true$/TRADING_PAUSED=false/' .env` for now (verified working tonight).
  - **Consequence** — Worth a follow-up issue. Engineering effort is trivial (mirror of `_pause_trading_in_env`); UX value is real (matches the `--pause` operational ergonomics).
