Standing invariants (from `CLAUDE.md` — restated because every Sprint 3 candidate touches risk):

- The LLM must never control risk parameters directly. Stops and targets come from `tools/risk.py`; the position monitor is rule-based; only `TeamLeaderAgent` places orders, and only with pre-approved values.
- Stops and take-profits execute server-side via Alpaca **OCO bracket orders submitted post-fill** — parent market → poll for fill → separate OCO with both legs anchored to the broker `filled_avg_price` (PR #144 changed this from atomic BRACKET).
- Fill-to-OCO window is typically <1s under normal load; if OCO submission fails, `notify_error` fires AND `trades.stop_loss` is written with the fill-anchored value so the position monitor's soft-stop has the right comparison price.
- Position monitor's top-of-loop `get_alpaca_positions()` call has its own try/except (fail-CLOSED): a transient broker error skips just that cycle, suppresses the `daily_stats` write, returns empty list; cron's next hourly fire retries.
- Team Leader Discord summary counts and `agent_logs.output_summary` are derived from a deterministic `_order_outcomes` ledger, not LLM prose. The system-prompt instruction is belt-and-braces only.
- Morning scan must run **pre-market** (cron `25 13 * * 1-5` UTC). Running after 13:30 UTC produces ~zero `volume_ratio` and kills every entry.
- `TRADING_PAUSED=true` halts new entries but does not affect the position monitor. Faster path: `python main.py panic --pause`.
- Free Alpaca paper accounts require `DataFeed.IEX`. Controlled via `DATA_FEED` env var.
- Every Python file starts with `from __future__ import annotations` (Python 3.9 runtime).
- `place_order(dry_run=True)` runs the deterministic safety stack (#127). Use `python main.py scan --dry-run` as a smoke test before any production-bound change to risk/order-placement code.
